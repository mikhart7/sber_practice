# Текстовые эмбеддинги финансовых новостей, допускающие восстановление смысла

Отчёт по учебной практике (НИР), СПбГУ, программа бакалавриата «Науки о данных». Полный текст с постановкой задачи, обзором литературы и всеми экспериментами — в [diplom.pdf](diplom.pdf).

[Рецензия](Рецензия_Зайцев_АА_Михеев.pdf): Зайцев Алексей Алексеевич -  заведующий лабораторией прикладных исследований «Сколтех — Сбербанк» (LARSS) Центра искусственного интеллекта Сколтеха;

Задача: построить компактный автокодировщик текста (encoder–decoder), который сжимает предложение в **один вектор фиксированной размерности** `S`, из которого затем можно восстановить текст с сохранением основного смысла (не обязательно дословно).

## Зачем

Рассматривается мультимодальная модель, которая по разнородным входным данным — числовым финансовым временным рядам, табличным данным, новостному контексту — предсказывает финансовые показатели (индексы, курсы валют, вероятность дефолта) и одновременно порождает текстовую интерпретацию, объясняющую эти предсказания.

Прямая авторегрессионная генерация текста внутри такой модели нежелательна: текстовая компонента loss будет доминировать и ухудшать качество предсказания числовых показателей. Решение:

1. **Препроцесс.** Обучающие текстовые интерпретации заранее кодируются обученным encoder в латентные векторы; сам encoder дальше в пайплайне не используется.
2. **Обучение мультимодальной модели** — предсказывать латентный вектор интерпретации по входному контексту (в генеративной парадигме или через cosine similarity loss).
3. **Декодирование** — предсказанный вектор подаётся в обученный decoder, который восстанавливает текст; при необходимости decoder дообучается совместно с мультимодальной моделью.

Отсюда два требования к автокодировщику: decoder должен быть компактным (быстрый инференс), а латентное представление — вектором фиксированной размерности, а не последовательностью скрытых состояний.

Похожие идеи (обучаемый `[mem]`-токен, восстанавливающий до 1568 токенов из одного вектора) показаны в [Cramming 1568 Tokens into a Single Vector and Back Again](https://arxiv.org/abs/2502.13063) и [Exploring the Latent Capacity of LLMs for One-Step Text Generation](https://arxiv.org/abs/2505.05439), но в обеих работах эмбеддинг оптимизируется индивидуально под каждый текст (тысячи шагов градиентного спуска на пример), а построение полноценного encoder оставлено как открытая задача. Этот проект решает именно её: encoder кодирует произвольный текст в вектор за один прямой проход.

## Метод

```
TEXT --tokenizer+emb--> (B,T,H) --SENTENCE ENCODER--> (B,S) --SENTENCE DECODER--> (B,T,V) --tokenizer+emb--> TEXT
```

**Encoder** — предобученный [FinBERT](https://arxiv.org/abs/1908.10063) (`yiyanghkust/finbert-tone`), веса заморожены. Агрегация контекстных эмбеддингов токенов в один вектор предложения — двумя способами:
- **CLS-эмбеддинг** — представление специального `[CLS]`-токена;
- **Attention pooling** — агрегация с обучаемыми весами внимания; работает заметно лучше и, в отличие от CLS, позволяет независимо задавать размерность `S`.

**Decoder** обучается с нуля, реализовано два варианта:
- **прямой (одношаговый)** — на основе Transformer Encoder (self-attention без маскирования), все токены предсказываются одновременно: `P(tgt[1:T] | s)`;
- **авторегрессионный** — на основе Transformer Decoder (masked self-attention + cross-attention на вектор предложения как context): `P(tgt[n+1] | tgt[1:n], s)`. Значительно лучше по качеству, но медленнее в инференсе.

**Функции потерь**: базовая — cross-entropy на реконструкцию исходного текста. Она не учитывает смысл как таковой, поэтому дополнительно реализованы функции потерь на уровне смысла предложения:
- **sent_sim_loss** — косинусное расстояние между эмбеддингами (`sentence-transformers/paraphrase-mpnet-base-v2`) исходного и сгенерированного текста, с пробросом градиента через Gumbel-Softmax + Straight-Through Estimator. Оказалась нестабильной при обучении, применима только как регуляризатор с малым весом поверх CE.
- **paraphrase loss** — для каждого примера генерируется K=3 перефразировки (`ramsrigouthamg/t5-large-paraphraser-diverse-high-quality`), и decoder обучается восстанавливать по тому же эмбеддингу не только исходный текст, но и любую из них. Испробованы три способа агрегации CE по исходнику и перефразам: среднее, минимум, гармоническое среднее (F1-like). Даёт наибольший прирост качества восстановления смысла.

Есть и более ранняя серия экспериментов на чистых RNN (`rnn/`) — она не оправдала себя: прямое обучение векторов через mse/cos loss не сходилось, а авторегрессионная постановка давала accuracy восстановления токена ≈0.2. Это и обосновало переход к архитектуре на основе предобученного FinBERT.

## Данные

[Financial News Headlines Data](https://www.kaggle.com/datasets/notlucasp/financial-news-headlines) (Kaggle) — заголовки финансовых новостей с CNBC, The Guardian и Reuters за 2018–2020 гг. Всего 53 370 заголовков, разбиение 90% train / 10% validation. Лежат в [finance_dataset/](finance_dataset/).

## Метрики

- **Accuracy** — доля совпавших токенов при позиционном сопоставлении.
- **BERTScore** (`microsoft/deberta-xlarge-mnli`) — семантическая метрика по попарному косинусному сходству токенов.
- **Paraphrase similarity (paraph_sim)** — косинусное сходство эмбеддингов предложений (`sentence-transformers/paraphrase-mpnet-base-v2`, dim 768) между исходным и восстановленным текстом.

## Результаты

Сравнение архитектур декодера/пулинга (validation):

| Модель | S | Accuracy | BERTScore |
|---|---|---|---|
| Прямой декодер | 1568 | 0.357 | — |
| Авторегрессионный, CLS | 768 | 0.406 | 0.58 |
| Авторегрессионный, Attention Pooling | 768 | 0.502 | 0.65 |
| Авторегрессионный, Attention Pooling | 2560 | 0.552 | 0.675 |

Авторегрессионный decoder с attention pooling однозначно лучше; качество растёт с увеличением размерности эмбеддинга `S`.

Замена жадной генерации на beam search снижает число повторов/заиканий и повышает paraph_sim:

| beam_width | 1 | 5 | 10 |
|---|---|---|---|
| paraph_sim | 0.665 | 0.687 | 0.689 |

Добавление paraphrase loss повышает top-5 accuracy умеренно в среднем (CE: 0.77 → F1-агрегация: 0.78), но если считать top-5 accuracy отдельно по каждой перефразе и усреднить — модель с paraphrase loss достигает **0.9** против **0.6** у базовой (на обучающих данных), т.е. заметно лучше сохраняет именно смысл, а не точную формулировку.

**Итоговые метрики лучшей модели**: paraph_sim = 0.69 (beam_width=5), val_accuracy = 0.659, BERTScore = 0.7.

Проверка на более длинных новостных описаниях (вне распределения по длине относительно заголовков): accuracy = 0.568, paraph_sim = 0.595 — качество ожидаемо падает, но не разрушается.

Устойчивость к шуму (важно для сценария, где вектор предсказывается другой моделью с некоторой ошибкой): при добавлении гауссова шума N(0, σ) к эмбеддингу — при σ=0.1 BERTScore практически не меняется, при σ=1.0 падает более чем на 10%.

Примеры восстановления и визуализация латентного пространства (перефразы одного предложения образуют компактный кластер после PCA) — в [diplom.pdf](diplom.pdf), разделы 2.9 и 3.

## Как запустить

Ноутбуки писались и запускались в Kaggle/Colab с GPU, поэтому в них зашиты соответствующие пути (`/kaggle/input/...`, `/content/drive/...`) — при запуске в другом окружении их нужно поменять на свои (путь к `finance_dataset/`, путь для сохранения чекпоинтов). Готового `requirements.txt` нет: зависимости ставятся по ходу выполнения ячеек (`!pip install ...`).

Основные зависимости:
- `torch`, `transformers`
- `lightning==2.4.0` (обучение оформлено как `LightningModule`/`Trainer`)
- `sentence-transformers` (`paraphrase-mpnet-base-v2` — метрика paraph_sim)
- `bert-score` (`microsoft/deberta-xlarge-mnli` — метрика BERTScore)
- `pandas`, `numpy`, `scikit-learn`
- `datasets` (только для `rnn/`, датасет multi30k)
- `plotly` (визуализация эмбеддингов через PCA, необязательно)

Порядок запуска основного подхода:
1. Открыть `finbert_encoder_decoder/finbert_autoregessive_base.ipynb` (или один из вариантов с другой функцией потерь).
2. Поправить путь до `finance_dataset/*.csv`.
3. Либо обучить модель с нуля (`L.Trainer(...).fit(...)`), либо подгрузить готовые веса: [веса моделей на Google Drive](https://drive.google.com/drive/folders/1RJ5vnuOkHi-3YjIYfPVi4XofTcMNFlDK?usp=drive_link).
4. Ячейки с генерацией (`generate_from_embedding`, beam search) кодируют предложение в эмбеддинг и раскодируют обратно — это основной сценарий использования модели.

## Направления дальнейших исследований

- **Масштабирование decoder-а**: сейчас decoder обучается с нуля, что ограничивает его языковые возможности; использование предобученной LLM (LLaMA, Pythia) в роли decoder, инициализированного латентным вектором через cross-attention/prefix, должно повысить связность генерируемого текста.
- **Интеграция в мультимодальную модель**: обучение модели предсказывать латентный вектор по финансовому контексту (временные ряды, табличные данные) с последующим совместным дообучением decoder.
- **Перенос на другие домены**: подход не привязан к финансовой тематике и может быть применён в медицинских, юридических и других мультимодальных системах, где нужна интерпретируемость предсказаний.
- **Компромисс размерность–качество**: систематическое построение кривых rate-distortion для обученного encoder.
